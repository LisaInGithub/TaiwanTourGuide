# 台灣小導遊 — 產品設計文件

## 1. 產品定位
一個「放在口袋裡的導遊」:幫來台灣玩的旅客(國內外自由行)決定 **去哪裡玩**、**怎麼過去**、**吃什麼**。

| 目標族群 | 痛點 | 我們的解法 |
|---|---|---|
| 第一次來台的自由行旅客 | 不知道去哪、不懂交通系統 | 依興趣推薦 + 一鍵產生每日行程 |
| 國內週末出遊族 | 懶得做功課 | 「問導遊」直接問、立刻得到答案 |
| 親子家庭 | 需要雨天備案、不想太累 | 親子/室內標籤、悠閒步調 |

## 2. 核心功能(原型已實作)
1. **💬 問導遊**:自然語言提問,例如「台北去台南要多久?」「花蓮三天怎麼玩?」「哪裡看夕陽最美?」。
   - 在 claude.ai 開啟時由 **Claude** 回答(`js/ai-guide.js`):Claude 透過 4 個工具查 App 內資料(查地點、搜景點、查路線、排行程)後再回答,避免編造班次與票價。
   - 無法使用 AI 時(直接開檔、離線、未授權)自動改用關鍵字版(`js/guide.js`):可辨識交通、行程天數、美食種類與夕陽/日出等關鍵字。
2. **✨ 導遊推薦**:選擇興趣(自然、老街、夜市、溫泉、親子、雨天室內…)與地區,依標籤比對分數排序景點(`recommend()`)。
3. **🗓️ 自動排行程**:輸入出發地、天數、步調與偏好,系統會:
   - 在目前城市依分數排入景點,直到當日時數用完;
   - 城市玩完後,挑「分數高、車程短」的下一站(分數 ÷ (1 + 車程小時));
   - 夜市類景點自動排在晚上,每天附一個在地美食推薦;
   - 可選擇最後一天回到出發地(預留回程時間)。
4. **🚆 交通規劃**:高鐵、台鐵、捷運、客運、飛機、渡輪組成路網,以 Dijkstra 演算法搜尋,提供「最快 / 最省錢 / 最少轉乘」三種方案;同一條路線的連續站會合併成一段,轉乘預留 15 分鐘;離島不會被當成轉乘點。
5. **🍜 吃喝玩樂**:依城市列出小吃、夜市、伴手禮與景點,可直接開 Google 地圖找店家。
6. **⭐ 收藏 + 串聯路線**:收藏的景點可排序,系統自動算出城市間的交通。
7. **📍 附近景點**:用 GPS 找出最近的景點。
8. **離線可用(PWA)**:可加到手機主畫面,收訊不好也能看。

## 3. 資訊架構
```
底部分頁:導遊(問答+推薦+附近) | 行程 | 交通 | 吃喝玩樂 | 收藏
```

## 4. 技術架構(原型)
- 純前端 HTML/CSS/ES Modules,零依賴,方便展示與後續改寫成 App。
- `js/data.js`:地點、景點、美食、交通路網(資料與邏輯分開,之後可換成 API)。
- `js/planner.js`:路線搜尋;`js/itinerary.js`:推薦與行程;`js/guide.js`:問答;`js/geo.js`:距離與地圖連結。
- `tests/`:Node 內建測試框架,`npm test`。

## 6. 資料正確性原則
- 票價、時間均為 **參考值**,畫面皆標示並附官方訂票連結。
- 有安全疑慮的景點(如震後的太魯閣、蘇花公路)在提示中提醒查詢官方公告。
